# MCP Hooks for Handbags

Handbags can **optionally** ship an `mcp/` folder that declares one or more
[Model Context Protocol](https://modelcontextprotocol.io) servers. When
present, the handbag exposes their tools to the agent alongside its native
Python toolsets — no changes to `TOOLS.py` required.

This is **fully optional**. A handbag with no `mcp/` folder behaves exactly as
before. Everything here is additive.

---

## Directory layout

```
my_agent/
├── SOUL.md
├── handbag.yaml
├── tools/
│   └── ...
├── skills/
├── rag/
├── memory/
└── mcp/                          ← OPTIONAL
    ├── filesystem.yaml           ← one manifest per MCP server
    ├── web_search.yaml
    └── README.md                 ← generated by create_structure()
```

- **One YAML file per server.** The filename stem (minus `.yaml`/`.yml`) is
  the canonical `server_id`. It must match `^[a-zA-Z0-9][a-zA-Z0-9_.-]{0,63}$`.
- Subdirectories under `mcp/` are scanned recursively, so you can group
  manifests (`mcp/local/filesystem.yaml`, `mcp/remote/search.yaml`) — the
  stem is still the ID, so **stems must be unique** across the whole tree or
  last-loaded wins.
- Files starting with `.` are ignored. Non-YAML files are ignored.

## Manifest schema

```yaml
title: Filesystem             # optional, defaults to server_id
description: >-               # optional, surfaced to the LLM in the catalog
  Read and write files inside the agent workspace.
enabled: true                 # optional, defaults to true
transport: stdio              # REQUIRED: stdio | http | sse

# ── stdio transport (local subprocess) ──
command: npx                  # REQUIRED for stdio
args: ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"]
env:                          # optional
  NODE_ENV: production

# ── http / sse transports (remote endpoint) ──
# url: http://localhost:8765/mcp      # REQUIRED for http/sse
# headers:                            # optional
#   Authorization: "Bearer ${MCP_TOKEN}"

security:
  allow_file_write: false     # safe default
  allow_shell: false          # safe default
  allowed_paths: []           # empty = no manifest-level whitelist
  denied_tools: []            # hard denylist
  approval_required: false    # force interactive approval

timeout_seconds: 30           # per-request hint, integer, positive
```

Every key except `transport` and the transport-specific requirement
(`command` for stdio, `url` for http/sse) is optional. The `security` block
accepts any subset of its keys — the rest inherit the safe defaults shown.

### Unknown security keys

Unknown keys inside `security:` trigger a warning but do **not** fail the
load. This keeps forward compatibility with future host-enforced keys.

## Python API

The integration lives in two modules:

| Module | Purpose |
| --- | --- |
| `lollms_personality.mcp_hooks` | Parsing, validation, the `MCPServerSpec` dataclass |
| `lollms_personality.handbag` | Auto-discovery from `<handbag>/mcp/`, convenience accessors |

### Loading

```python
from lollms_client.lollms_personality import Handbag

handbag = Handbag("path/to/my_agent")

# Every loaded manifest, enabled or not, sorted by server_id.
for spec in handbag.mcp_servers:
    print(spec.server_id, spec.transport, spec.enabled)

# Only the ones a host should actually connect to.
for spec in handbag.enabled_mcp_servers:
    if spec.is_stdio:
        launch(spec.command, spec.args, env=spec.env)
    else:
        connect(spec.url, headers=spec.headers)
```

### `MCPServerSpec`

A frozen, validated description. Every attribute is documented in
`mcp_hooks.py`. Key projections:

- `spec.is_stdio` → `True` for `transport: stdio`
- `spec.is_network` → `True` for `http` / `sse`
- `spec.to_manifest_dict()` → JSON-safe dict (paths stringified)
- `spec.security` → always contains all five keys documented above

### Dynamically adding servers (no YAML)

Hosts that build specs from a GUI wizard can register directly:

```python
from lollms_client.lollms_personality.mcp_hooks import MCPServerSpec

handbag.register_mcp_server(MCPServerSpec(
    server_id="scratch",
    source_path=Path("/virtual"),          # no file needed
    title="Scratch Pad",
    description="Ephemeral in-memory tools.",
    enabled=True,
    transport="stdio",
    command="python",
    args=["-m", "my_mcp_server"],
))
```

Re-registering the same `server_id` replaces the previous spec (idempotent).

### Catalogue / GUI summary

```python
summary = handbag.mcp_manifest_summary()
# -> List[Dict[str, Any]] with `env` and `headers` values redacted to
#    "<redacted>" so the result can be logged or shown to the LLM safely.
```

## Failure handling

The subsystem is **fail-soft** by contract:

1. **Missing `mcp/` folder** → `handbag.mcp_servers == []`, no warnings.
2. **Malformed manifest** → skipped with a warning; siblings still load.
   The specific reason is captured in `handbag.mcp_warnings`.
3. **`yaml` import failure** → every manifest is skipped with a warning
   (should never happen — `pyyaml` is a hard dependency of `lollms_client`).
4. **Any unexpected exception during discovery** → caught at the `Handbag`
   level, logged, and the handbag constructs without MCP hooks. `mcp_servers`
   is guaranteed to be a list.

Host applications should **never assume** `mcp_servers` is non-empty.

## Security model

`mcp_hooks` only *parses and validates*. It never spawns processes or opens
sockets. Actual connection, subprocess launching, and enforcement of the
`security` block are the responsibility of the host (e.g. the LCP MCP toolset
loader at `tools_bindings/mcp/`).

The `security` block is **advisory**: it records the manifest author's intent.
Hosts are expected to:

1. Apply their own global policy **on top of** the manifest's posture.
2. Reject servers that request capabilities the host disallows.
3. Redact `env` / `headers` values from any log or LLM-facing catalogue
   (the provided `mcp_manifest_summary()` already does this).

Recommended default enforcement:

| Manifest field | Host action |
| --- | --- |
| `allow_file_write: false` | Reject `write_*`, `create_*`, `delete_*` tools |
| `allow_shell: false` | Reject `exec_*`, `shell_*`, `run_*` tools |
| `allowed_paths: [...]` | Sandbox tool arguments to the listed roots |
| `denied_tools: [...]` | Remove from the tool catalog entirely |
| `approval_required: true` | Route every call through user approval |

## Example: two-server handbag

```yaml
# mcp/filesystem.yaml
transport: stdio
command: npx
args: ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"]
security:
  allow_file_write: true
  allowed_paths: ["/workspace"]
```

```yaml
# mcp/web_search.yaml
transport: http
url: http://localhost:8765/mcp
headers:
  Authorization: "Bearer ${MCP_WEB_TOKEN}"
security:
  allow_file_write: false
  allow_shell: false
timeout_seconds: 15
```

Then:

```python
handbag = Handbag("my_agent")
assert {s.server_id for s in handbag.enabled_mcp_servers} == {
    "filesystem", "web_search"
}
```

## Scaffolding a new handbag

`Handbag.create_structure()` now creates `mcp/` with a `README.md` inside,
so new handbags immediately document the feature. The folder is empty of
manifests by default — fill it only if you want MCP tools.
